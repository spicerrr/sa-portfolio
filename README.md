## 01 · кейсы

### 🌱 движение партии и «Паспорт сорта»

[**открыть кейс →**](agritech/README.md)

**Задача.** Производство и склад описывают один и тот же физический объект по-разному: локальные коды, разные названия сортов, отдельные документы сбора и приёмки. Простого join по названию и дате недостаточно — появляются дубли, несопоставленные записи и спорные расхождения по массе.

**Что сделала.**
- разделила справочные сущности и производственные факты;
- ввела единый идентификатор сорта и mappings для локальных кодов источников;
- описала регистрацию партии, складское подтверждение и поведение при повторах / временной недоступности получателя;
- связала требования с API, моделью данных, сообщениями и сценариями приёмки;
- отдельно описала расчёт «Паспорта сорта», чтобы неполные данные не превращались в ложные «потери».

## 02 · коммерческий опыт

**«Агроном-Сад» · цифровая трансформация · с сентября 2025**

Работаю не с «агро как доменом», а с довольно переносимым набором задач: **ручные процессы → требования → данные → стыки систем → проверка результата**.

| Зона | Что делаю |
|:---|:---|
| **Требования и процессы** | Разбираю ручные / Excel-сценарии, фиксирую AS-IS, роли и точки принятия решений; из этого собираю требования к внутренним инструментам и TO-BE |
| **Данные и master data** | Разбираю сущности, атрибуты, ID, дубли и ownership; свожу локальные справочники к общей модели |
| **Стыки систем** | Описываю, какие данные рождаются в одном контуре и нужны другому, когда они должны передаваться и что считать ошибкой / расхождением |
| **Моделирование** | BPMN для процессов, ERD для данных, UML для состояний и взаимодействий |
| **BI / отчётность** | Формализую состав показателей, источники данных, правила расчёта и проверки; публичный пример — [«Паспорт сорта»](agritech/docs/variety-passport.md) |
| **Версионирование** | Git использую для скриптов и технических артефактов. GitLab-flow с MR / review / tags показан в [публичной реконструкции](agritech/docs/versioning.md), а не выдаётся за корпоративный процесс компании |

### один конкретный пример

В разных источниках один сорт мог жить под разными локальными кодами и названиями. Если связывать записи строкой вроде «Голден» / «Golden Delicious», ошибка становится вопросом времени.

В публичном кейсе я разложила проблему на системные правила: **единый ID сорта → mapping локальных кодов → состояние UNRESOLVED для неизвестных значений → отдельное согласование конфликтов**. Это уже не «почистить Excel», а определить, какую сущность система считает одной и той же и как это проверяется на границе нескольких источников.
