### 📦 движение партии

Оператор регистрирует сбор, кладовщик подтверждает приёмку, руководитель получает отчёт. У каждого участника свои документы и задачи, а данные о сорте и партии должны оставаться связанными.

В кейсе разобраны исходные источники, роли и пользовательские сценарии. Для целевого процесса описаны правила регистрации, модель данных и обмен между производством и складом. Например, повтор запроса после потери ответа возвращает прежний номер партии; разница производственной и складской масс сохраняется для сверки.

Публичная версия — обезличенная проектная реконструкция рабочего контекста; примеры данных условные.
