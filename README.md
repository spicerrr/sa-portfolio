## 01 · кейсы

### 🌱 движение партии: производство → склад → отчётность

[**открыть кейс →**](agritech/README.md)

**Задача.** Производство и склад описывают один физический объект разными кодами и документами. Соединять записи только по названию сорта и дате нельзя: появляются дубли, несопоставленные записи и спорные расхождения по массе.

**Что сделано в публичной реконструкции.**
- справочные сущности отделены от производственных фактов;
- для локальных кодов описаны единый идентификатор сорта и правила соответствия;
- регистрация партии и складское подтверждение связаны общим идентификатором;
- для временной недоступности получателя и повторной доставки заданы отдельные сценарии;
- требования связаны с API, моделью данных, контрактами событий и проверками.

Это проектная реконструкция: промышленное внедрение и фактическая архитектура компании не заявляются.

## 02 · коммерческий опыт

**«Агроном-Сад» · цифровая трансформация · с сентября 2025**

Работаю с переносимым набором задач: **ручной процесс → требования → данные → взаимодействие систем → проверка результата**.

| Зона | Что делаю и что получается |
|:---|:---|
| **Требования и процессы** | Разбираю ручные и Excel-сценарии, фиксирую AS-IS, роли и точки принятия решений; на выходе — требования к внутренним инструментам и описание TO-BE |
| **Справочные данные** | Разбираю сущности, атрибуты, идентификаторы, дубли и ответственность за данные; результат — единые правила идентификации и соответствий между источниками |
| **Стыки систем** | Фиксирую, какие данные создаёт один контур и использует другой, когда они должны передаваться и что считать ошибкой или расхождением |
| **Инциденты и качество данных** | Разбираю несопоставленные записи, дубли и расхождения показателей; фиксирую причину и правило дальнейшей обработки |
| **Моделирование** | BPMN — процессы; ERD — данные; UML — состояния и взаимодействия |
| **BI / отчётность** | Формализую показатели, источники и правила расчёта; публичный пример встроен в [модель данных](agritech/docs/data-model.md#variety-passport) |

### один конкретный пример

В разных источниках один сорт мог иметь разные локальные коды и названия: «Голден», «Golden Delicious», «ГОЛДЕН ДЕЛИШЕС». Сопоставление по строке ненадёжно.

В публичном кейсе эта проблема разложена на системные правила: **единый идентификатор сорта → соответствия локальных кодов → отдельное состояние для неизвестного значения → ручное согласование конфликта**.

## 03 · стек

| Область | Уровень | Что использую |
|:---|:---|:---|
| **Данные** | использую уверенно | SQL · PostgreSQL |
| **Моделирование** | использую уверенно | BPMN · UML · ERD |
| **Синхронные интеграции** | проектная практика | REST / HTTP · OpenAPI / Swagger · Postman |
| **Событийные интеграции** | проектная практика | RabbitMQ · контракты событий · повторная доставка · DLQ · идемпотентность · идентификатор корреляции |
