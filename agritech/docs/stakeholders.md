# 👥 заинтересованные стороны

Реестр описывает функциональные роли процесса. Один человек может совмещать роли; конкретные должности и линия подчинения компании не заданы. Заинтересованная сторона может согласовывать решение, не выполняя действий в системе.

## Интересы и влияние

| ID / роль | Интерес и проблема | Данные / решения | Влияние и участие | Критерий результата |
|:---|:---|:---|:---|:---|
| SH-01 Руководитель производства | Сбор продолжается при недоступности склада; понятна полнота отчёта | Граница регистрации, исключения производства | Высокое; согласует процесс | Подтверждённый сбор не теряется и не вводится повторно |
| SH-02 Главный агроном | Сорт и площадь соответствуют посадкам | Смысл сорта, участок–сезон–сорт, плодоносящая площадь | Высокое; согласует агрономические данные | Урожайность считается по согласованной площади |
| SH-03 Оператор производственного учёта | Однократно ввести подтверждённый сбор и получить ID | Журнал сбора, дата, масса, документ источника | Среднее; интервью и проверка UC-02 | Понятен результат запроса после разрыва связи |
| SH-04 Ответственный за НСИ | Устранить дубли без искажения истории | Канонические записи, ключи источников, соответствия | Высокое в НСИ; выполняет UC-01 | Нет неоднозначных утверждённых ключей |
| SH-05 Кладовщик | Принять физический груз и сохранить собственное измерение | Масса приёмки, складской документ | Среднее; выполняет UC-03 | Разница весов видна, производственный факт не переписан |
| SH-06 Руководитель склада | Исключить двойную ожидаемую приёмку и необъяснимые расхождения | Правила полной приёмки, разбор расхождений | Высокое; согласует складскую часть | Повтор сообщения не порождает второй документ |
| SH-07 Экономист / учёт | Получать идентифицируемые факты для ERP | Номенклатура, учётные документы, методика затрат | Высокое по учёту; консультирует | Сохраняется связь с первичным документом; затраты не смешаны с массой |
| SH-08 Логист | Сопоставлять перевозку с грузом | Рейс, транспортный документ | Консультация на границе | В первой версии его данные не подменяют идентичность партии |
| SH-09 Аналитик BI | Воспроизвести показатель и найти неполные связи | Формула, гранулярность, контрольные суммы | Среднее; выполняет UC-04 / UC-05 | Итог раскрывается до исходных фактов |
| SH-10 Команда ЦТ / аналитик системы | Согласовать процесс, данные, контракты и ограничения | Спецификации и трассировка | Координация, без полномочий исправлять бизнес-факты | Изменение отражено во всех зависимых артефактах |
| SH-11 Разработка / сопровождение | Восстановить обмен и диагностировать сбой | Реализация, журнал, DLQ | Техническое решение и поддержка | Повторная доставка безопасна и прослеживаема |

## Конфликты требований

| Конфликт | Решение в данном срезе | Кто согласует |
|:---|:---|:---|
| Производство хочет сразу подтвердить сбор; склад доступен не всегда | Регистрация завершается локально, склад получает событие позднее | SH-01, SH-06; FR-03, NFR-01 |
| Склад доверяет своим весам; производство — своим | Хранить два измерения, анализировать разницу без автоматического списания | SH-02, SH-06, SH-07; BR-03 |
| Пользователь хочет подобрать сорт по имени; НСИ требует достоверности | Нормализация предлагает кандидата, утверждение требует подтверждения владельца | SH-02, SH-04; BR-01 |
| Руководитель хочет итоговую урожайность; часть данных не связана | Показывать полноту отдельно и не выдавать неполную приёмку за потери | SH-01, SH-09; FR-05 |

## Полномочия на согласование

`A` — один ответственный за итог решения, `R` — исполнитель, `C` — консультируется, `I` — информируется. Матрица относится к решениям, а не заменяет права доступа приложения.

| Решение | A | R | C | I |
|:---|:---|:---|:---|:---|
| Признать исходный код тем же сортом | SH-02 | SH-04 | SH-03, SH-07 | SH-09, SH-10 |
| Утвердить площадь участка в сезоне | SH-02 | SH-03 | SH-09 | SH-01 |
| Подтвердить факт сбора | SH-01 | SH-03 | SH-02 | SH-06 |
| Подтвердить приёмку | SH-06 | SH-05 | SH-03 | SH-07, SH-09 |
| Согласовать формулу урожайности | SH-02 | SH-09 | SH-01, SH-07 | SH-10 |
| Выпустить контракт обмена | SH-10 | SH-11 | SH-01, SH-06 | SH-09 |
| Вернуть сообщение из DLQ | SH-11 | SH-11 | SH-10; SH-04 при ошибке справочника | Владелец затронутого факта |

Техническая роль `production_operator` соответствует SH-03; `mdm_reader` даёт чтение соответствий, но не право их утверждения. Кладовщик действует в WMS. Изменения НСИ в первом срезе согласуются в управляемом реестре и выпускаются по [регламенту версий](versioning.md).
