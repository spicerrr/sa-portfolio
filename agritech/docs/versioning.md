# 🌿 версии и согласование

Git хранит историю схем, контрактов и документации; GitLab организует Merge Requests, доступ и проверки. Основания выбора платформы приведены в [контексте](context.md).

## Один запрос на изменение

Пример: добавить исходный ключ партии для защиты от повторного ввода.

| Шаг | Артефакт / контроль |
|:---|:---|
| Постановка | Цель, источник запроса, BR-02 и критерий AC-03 |
| Ветка | `feature/source-record-identity` от `main` |
| Изменение | Требования, OpenAPI, SQL UNIQUE, тестовые данные и сценарий проверки |
| MR | Причина изменения, затронутые контракты, совместимость, результат проверки |
| Review | Аналитик проверяет бизнес-смысл; разработчик — контракт и миграцию; владелец данных — идентичность источника |
| Merge | После согласования и проверки артефактов |
| Тег | `agritech-v1.0.0` фиксирует согласованный срез; тег не ставится только ради оформления |

Согласованность важнее одинакового номера во всех файлах: версия события меняется при несовместимом контракте, версия API — при изменении его поверхности, версия документа фиксирует редакцию требований.

## Выпуск соответствия НСИ

UC-01 оформляется изменением управляемого реестра: SH-04 указывает локальный ключ и основание, SH-02 подтверждает сорт. В MR включаются экспорт соответствий, список затронутых фактов и результат проверки конфликтов. SH-10 проверяет зависимые требования; SH-11 проверяет техническую загрузку. Merge не заменяет бизнес-согласование.

Экспорт `source_mapping` не хранит всю историю утверждения; она сохраняется в реестре решений и выпуске. Исходные корпоративные данные и секреты в публичный репозиторий не включаются. Git предназначен для схем, контрактов, кода и обезличенных примеров; промышленный журнал сбора не версионируется коммитами.

## Проверка

`requirements-check.txt` содержит зависимости валидатора. [Шаблон GitLab CI](../gitlab-ci.example.yml) запускает его из корня `sa-portfolio`. Шаблон не подключён к реальному корпоративному проекту; в этой публикации проверка выполнена локально.

MR должен содержать результат проверки и ограничения: отсутствие работающего API-стенда, брокера и интеграционных испытаний нельзя заменять утверждением «всё протестировано».

## Диаграммы

PlantUML 1.2026.1; исходники используют `!pragma layout smetana`. Для обновления встроенных SVG:

```bash
java -Djava.awt.headless=true -jar plantuml.jar -tsvg -o rendered agritech/diagrams/*.puml
```

Изображения коммитятся вместе с `.puml`. Валидатор проверяет наличие изображений и отсутствие текста ошибки рендеринга; семантика и читаемость проверяются при review.
