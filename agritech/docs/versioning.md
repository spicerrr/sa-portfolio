# Версии и согласование спецификаций

Публичные материалы хранятся в этом GitHub-репозитории. Ниже описан порядок согласованного изменения требований, API, диаграмм и SQL. Файл GitLab CI служит примером переноса автоматических проверок в проектный процесс.

## Пример: защита от повторного ввода документа

| Шаг | Что делает команда |
|:---|:---|
| Описать изменение | Аналитик фиксирует цель, источник запроса, правило BR-02 и проверку AC-03 |
| Подготовить редакцию | Автор изменения создаёт ветку `feature/source-record-identity` от `main` и обновляет свою часть документации |
| Обновить связанные файлы | Меняются требования, OpenAPI, ограничение уникальности в SQL и тестовые данные |
| Предложить включение в основную ветку | В запросе на слияние (Merge Request) указываются причина, затронутые интерфейсы и результаты проверки |
| Проверить решение | Аналитик проверяет поведение; разработчик — API и схему; владелец данных — устойчивость исходного ключа |
| Включить изменение | После согласования и успешных проверок ветка объединяется с `main` |
| Зафиксировать выпуск | Тег, например `agritech-v1.0.0`, обозначает согласованную версию файлов |

Версия сообщения меняется при несовместимом формате, версия API — при изменении интерфейса, редакция требований — при изменении описанного поведения. Их номера могут различаться; важна согласованность конкретного выпуска.

## Изменение соответствий сортов

Ответственный за справочники указывает локальный код и основание, главный агроном подтверждает сорт. Команда проверяет затронутые исторические записи и загрузку изменённого файла. Версия включается в выпуск после подтверждения владельца данных.

Таблица `source_mapping` содержит актуальные соответствия; основание и историю согласования сохраняет реестр решений. Git хранит схемы, контракты, код и примеры. Производственный журнал и закрытые данные размещаются в предназначенных для них системах.

## Автоматические проверки

[Файл GitLab CI](../gitlab-ci.example.yml) задаёт запуск валидатора из корня репозитория. Зависимости перечислены в `requirements-check.txt`. В запросе на слияние указываются выполненные проверки и результаты; проверка файлов и испытание работающего обмена учитываются отдельно.

## Обновление диаграмм

UML-диаграммы построены в PlantUML 1.2026.1; исходники используют `!pragma layout smetana`.

```bash
java -Djava.awt.headless=true -jar plantuml.jar -tsvg -o rendered agritech/diagrams/*.puml
```

Изображения SVG обновляются вместе с `.puml`. Валидатор проверяет наличие изображений и отсутствие ошибок построения. Содержание и читаемость проверяет автор изменения и рецензент.

Обзорная схема [источников и расчёта](../diagrams/rendered/passport-data.svg) хранится как редактируемый SVG. При изменении правил расчёта обновляется вместе с моделью данных.
