# 📋 требования к системе

**BG-01 — бизнес-цель:** сопоставлять сбор и складскую приёмку по идентификатору партии, сохраняя исходные документы и отдельные измерения для отчёта.

В каталоге `BR` обозначает бизнес-правило, `FR` — функцию системы, `NFR` — требование к качеству работы, `CON` — технологическое ограничение. Идентификаторы используются для связи со сценариями и проверками.

| ID | Тип | Требование |
|:---|:---|:---|
| BR-01 | Бизнес-правило | Один локальный код сорта в одной системе связан не более чем с одним единым сортом. Если есть несколько кандидатов, выбор подтверждает ответственный за справочники и главный агроном. |
| BR-02 | Бизнес-правило | Одна строка исходного документа сбора создаёт не более одной производственной партии. Уникальность определяется системой-источником и устойчивым ключом строки документа. |
| BR-03 | Бизнес-правило | Масса сбора и масса приёмки сохраняются отдельно. После регистрации исходные факты не перезаписываются; корректировка оформляется отдельным процессом. |
| BR-04 | Правило расчёта | Урожайность сорта за сезон равна массе сбора, делённой на плодоносящую площадь этого сорта. Каждый участок включается в площадь один раз, в том числе при отсутствии сбора. |
| FR-01 | Функция | При поиске сорта система использует только утверждённое соответствие локального и единого кодов. Неизвестный код возвращает `404 MAPPING_NOT_FOUND`. При регистрации проверяются активность сорта и его связь с участком и сезоном. |
| FR-02 | Функция | При регистрации клиент передаёт ключ запроса в заголовке `Idempotency-Key`. Повтор того же содержимого с тем же ключом возвращает исходные `201` и ответ. Другое содержимое с прежним ключом или повтор исходного документа с новым ключом возвращают `409`. |
| FR-03 | Функция | Производственная система одной транзакцией сохраняет партию, результат запроса и сообщение для отправки. Сообщение передаётся RabbitMQ отдельным процессом после завершения регистрации. |
| FR-04 | Функция | При получении подтверждения WMS система сохраняет складской номер, массу и время приёмки для указанной партии. Повторное сообщение не создаёт вторую приёмку и не меняет массу сбора. |
| FR-05 | Функция | Отчёт показывает сбор, подтверждённую приёмку, разницу сопоставленных масс и урожайность по сорту и сезону. Для каждого набора фактов доступны источник и время обновления. |
| FR-06 | Функция | Выпуск справочника соответствий содержит автора, согласующего, основание и дату решения. Переназначение локального кода другому сорту блокируется до проверки связанных исторических фактов. Согласование выполняется в управляемом реестре. |
| FR-07 | Функция | При подготовке старых данных сохраняются снимок источника, исходная строка, её устойчивый ключ и решение о загрузке. Идентичные повторы отделяются от конфликтующих версий. Неопределённые строки не регистрируются автоматически. |
| NFR-01 | Надёжность | При недоступности WMS в течение 30 минут регистрация сбора продолжается. После восстановления сохранённые сообщения доставляются; повторная доставка не создаёт дополнительные партии и приёмки. |
| NFR-02 | Доступ | Регистрировать сбор может роль оператора производства `production_operator`; читать соответствия — роли `mdm_reader` и `production_operator`. Отсутствующий или недействительный токен возвращает `401`, недостаточные права — `403`. Проверяются подпись, срок действия, издатель и назначение токена JWT. |
| NFR-03 | Диагностика | Запрос и связанные сообщения содержат общий `correlationId`. Журнал позволяет найти исходный документ, результат действия и число попыток отправки. Токены доступа и полные тела запросов не записываются. |
| NFR-04 | Актуальность | При штатной работе подтверждение складской приёмки отражается в отчёте не позднее чем через 5 минут. При превышении срока отчёт показывает признак устаревания. |
| CON-01 | Технология | API описывается в OpenAPI 3.0.3; данные производственной системы хранятся в PostgreSQL; сообщения между системами передаются через RabbitMQ. |

## Правила ввода

Масса передаётся в килограммах: положительное число с точностью до 0,001 кг. Дата сбора не позже текущей даты сервера в UTC и относится к указанному календарному сезону. Сорт должен быть активен и совпадать с сортом участка в этом сезоне.

`sourceRecordId` — устойчивый ключ документа и строки в системе-источнике. Он не меняется при повторной выгрузке. Ключ запроса `Idempotency-Key` — UUID; результат хранится не менее 24 часов отдельно для пользователя и операции. Для сравнения запросов порядок полей JSON не учитывается. После удаления результата запроса постоянное ограничение уникальности исходного документа продолжает защищать от дублей.

Уникальность проверяется ограничениями БД, включая одновременные запросы. Проверки, выполненной только перед записью, недостаточно: два запроса могут пройти её одновременно.
