# 📋 требования v1.0

**BG-01:** связать производственный факт и складскую приёмку без ручного соединения по названиям, сохранив происхождение данных для аналитики.

Идентификатор требования не задаёт его уровень. Бизнес-правило ограничивает допустимые факты; функциональное требование описывает поведение системы; требование качества задаёт измеримое свойство этого поведения. Все числовые пороги ниже — условия демонстрационной модели.

| ID | Тип / уровень | Формулировка |
|:---|:---|:---|
| BR-01 | Правило / бизнес | Один ключ `(sourceSystem, entityType, sourceId)` соответствует не более чем одному каноническому ID. Автоматический выбор между неоднозначными кандидатами запрещён. |
| BR-02 | Правило / бизнес | Одна исходная запись сбора порождает не более одной партии: уникальность `(sourceSystem, sourceRecordId)`. |
| BR-03 | Правило / бизнес | Масса сбора и масса приёмки — разные факты; каждый изменяется только владельцем. В версии 1.0 зарегистрированные факты неизменяемы. |
| BR-04 | Правило / аналитика | Урожайность сорта за сезон = масса сбора / площадь плодоносящих участков этого сорта в сезоне. Участок входит в знаменатель один раз, в том числе при отсутствии сбора. |
| FR-01 | Функциональное / система | MDM разрешает ключ источника только по утверждённому mapping; неизвестный ключ возвращает `404 MAPPING_NOT_FOUND`. Production проверяет активность сорта и его соответствие участку и сезону. |
| FR-02 | Функциональное / система | Регистрация принимает `Idempotency-Key`; повтор одинакового запроса в рамках субъекта и операции возвращает исходный `201` и тело. Изменение тела при прежнем ключе или повтор исходной записи с новым ключом возвращает `409`. |
| FR-03 | Функциональное / система | Production атомарно сохраняет партию, результат запроса и outbox; публикация не входит в пользовательскую транзакцию. |
| FR-04 | Функциональное / система | Получатель `warehouse.lot.received.v1` сохраняет одну приёмку на `batchId`, массу, `lotId` и время, не перезаписывая массу сбора. |
| FR-05 | Функциональное / система | Витрина выдаёт сбор, приёмку, разницу и урожайность по сорту и сезону; источник и время актуальности показаны для каждого набора фактов. |
| NFR-01 | Качество / надёжность | При недоступности WMS 30 минут Production продолжает регистрацию; после восстановления весь сохранённый outbox доставляется без повторного бизнес-эффекта. |
| NFR-02 | Качество / доступ | Регистрация доступна только роли `production_operator`; разрешение mappings — `mdm_reader` или `production_operator`; отсутствие/ошибка токена — `401`, недостаточные права — `403`. В тестовом контуре JWT проверяется по issuer/audience/подписи/сроку. |
| NFR-03 | Качество / наблюдаемость | У каждой регистрации и события есть `correlationId`; журнал содержит ID, исходную запись, результат и число попыток без токена и полного тела запроса. |
| NFR-04 | Качество / свежесть | При штатной доступности проекция отражает подтверждённое событие приёмки не позднее 5 минут; при превышении порога отчёт помечает данные как устаревшие. |
| CON-01 | Ограничение / решение | API описан OpenAPI 3.0.3, операционные данные — PostgreSQL, доставка событий — RabbitMQ. |

## Критерии регистрации

Масса — положительное число с точностью до 0.001 кг; `season` равен году `harvestDate` (календарный сезон модели). Дата не позже текущей UTC-даты сервера. Сорт и участок существуют в согласованной локальной реплике; привязка сорта к участку в сезоне совпадает. `sourceRecordId` — стабильный ключ источника, а не порядковый номер запроса.

Ключ идемпотентности — UUID, хранится минимум 24 часа вместе с каноническим хешем разобранного JSON (порядок полей не влияет). После истечения срока уникальность исходной записи продолжает предотвращать дубли. Проверки уникальности выполняются в БД, а не только предварительным SELECT.

## Открытые вопросы для следующей версии

Разделение и смешение партий; частичная приёмка; исправление факта; сезон вне календарного года; изменения посадок внутри сезона; допустимое расхождение весов; правило распределения затрат ERP. Эти вопросы не подменены произвольными правилами v1.
