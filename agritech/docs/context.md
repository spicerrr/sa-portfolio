# 🧭 предприятие и задача проекта

«Агроном-Сад» выращивает яблоки и управляет их движением от садовых участков до приёмки, хранения, сортировки и дальнейшей обработки. Для управления производством нужны связанные данные о посадках, сборе урожая, складской приёмке, качестве и затратах.

## Проблема

Производство, склад и учёт используют собственные справочники и документы. Один сорт может называться «Голден», «Golden Delicious» и «ГОЛДЕН ДЕЛИШЕС». Документ сбора и документ приёмки имеют разные номера. Поэтому при подготовке отчёта приходится отдельно подтверждать, что записи относятся к одному сорту и одной партии.

Пример: производство зарегистрировало 8420 кг урожая, склад принял 8370 кг. Нужно сохранить оба измерения, установить связь между документами и показать разницу 50 кг. Суммировать эти массы или заменять одно значение другим нельзя.

## Цель

Связать сбор и приёмку устойчивым идентификатором партии, согласовать коды сортов между источниками и подготовить данные для отчёта «Паспорт сорта». После регистрации сбора склад должен получить его реквизиты без повторного ручного ввода.

## Системы и их назначение

| Область | Назначение | Данные |
|:---|:---|:---|
| Производственный учёт — Production | Регистрировать сбор по участкам и сезонам | Участки, посадки, партии, масса сбора |
| Складская система — WMS | Оформлять приёмку и вести складские операции | Складская партия, масса приёмки, ячейки, остатки |
| Учётная система — ERP | Учитывать ресурсы, документы и затраты | Номенклатура, стоимость, затраты |
| Транспортная система — TMS | Планировать и учитывать перевозки | Рейсы и транспортные документы |
| Управление справочными данными — MDM | Согласовывать единые записи и соответствия локальных кодов | Сорта, коды источников, решения о сопоставлении |
| Отчётность — BI | Рассчитывать показатели по согласованным данным | Сбор, приёмка, урожайность, полнота данных |

Production и MDM обозначают функции решения; MDM может быть организован как управляемый реестр справочников. PostgreSQL хранит данные производственного учёта, REST API принимает запросы, RabbitMQ передаёт сообщения между системами. Git / GitLab используются для согласования версий схем, API и документации.

## Кто отвечает за данные

| Данные | Ответственный | Правило для остальных участников |
|:---|:---|:---|
| Сорт и соответствие кодов | Ответственный за справочники; главный агроном подтверждает сорт | Использовать согласованный код; похожее название не считается подтверждением |
| Участок, посадки, плодоносящая площадь | Производство / главный агроном | Учитывать сезон и единицу площади |
| Документ и масса сбора | Производственный учёт | Сохранять исходный документ и измерение |
| Документ и масса приёмки | Склад | Не менять производственную массу |
| Учётная стоимость и затраты | Экономист / ERP | Применять согласованную методику распределения затрат |
| Рейс | Логистика / TMS | Связывать перевозку с грузом и документами |
| Формула показателя | Владелец методики; аналитик BI реализует расчёт | Показывать источник, полноту и время обновления |

## Правила первой версии

| ID | Принятое правило | Влияние на решение |
|:---|:---|:---|
| A-01 | На одном учётном участке в сезоне выращивается один сорт | Посадка определяется участком и сезоном |
| A-02 | Одна партия принимается полностью и однократно | Один факт приёмки на производственную партию |
| A-03 | Сезон сбора совпадает с календарным годом | Дата сбора должна относиться к указанному сезону |
| A-04 | После регистрации факты сбора и приёмки сохраняются без изменения | Исправление оформляется отдельным процессом, не перезаписью исходной массы |
| A-05 | Каждая исходная строка имеет устойчивый ключ | Повтор выгрузки не создаёт новую партию |
| A-06 | Справочники передаются потребителям согласованными версиями | Регистрация проверяет локальную копию утверждённых данных |

Первая версия охватывает справочники сортов, регистрацию сбора, полную приёмку и показатели отчёта. Сортировка, смешение и разделение партий, частичная приёмка, перевозки и расчёт затрат относятся к следующим этапам. [Исходные данные](as-is-data.md) · [сценарии работы](use-cases.md).
