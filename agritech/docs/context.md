# 🧭 контекст и границы

## Основания описания

| Основание | Что известно | Что не установлено |
|:---|:---|:---|
| Рабочий опыт | Участие в цифровой трансформации, описание процессов и справочных данных, требования к ERP / WMS / TMS, «Паспорт сорта», оценка цифровой зрелости | Историческая схема БД, версии продуктов и фактический порядок внедрения |
| Предметная область | Сорта, участки, партии, операции, урожайность, качество и затраты; различия наименований между источниками | Точные формы документов и правила присвоения номеров |
| Публичная модель | Исходные структуры в [AS-IS](as-is-data.md), функциональные роли, целевые контракты | Эти структуры и роли не являются опубликованной оргструктурой или слепком систем компании |

Архитектура PostgreSQL / REST / RabbitMQ и процесс GitLab заданы для описанного решения. Числовые примеры синтетические. Допущения, влияющие на данные и поведение, перечислены ниже; их изменение требует пересмотра связанных артефактов.

## Граница системы

Production регистрирует производственный факт и хранит проекцию складской приёмки. Ответственный за справочные данные согласует сорт и соответствия локальных ключей. WMS ведёт складской факт; отчёт объединяет согласованные данные. Функциональные роли и владельцы решений описаны в [реестре заинтересованных сторон](stakeholders.md).

| Данные | Владелец в целевой модели | Ответственность потребителя |
|:---|:---|:---|
| Канонический сорт и соответствия | Ответственный за НСИ; главный агроном подтверждает смысл | Хранить локальный ключ и согласованный ID, не создавать сорт по похожему имени |
| Участок, посадки, плодоносящая площадь | Производство | Сохранять сезон и единицу площади |
| Факт сбора | Производство | Не заменять его складской массой |
| Складская приёмка, ячейки и остатки | Склад / WMS | Отличать полученную проекцию от фактического остатка |
| Учётная стоимость и затраты | Экономика / ERP | Не рассчитывать их из массы без правил распределения |
| Рейс | Логистика / TMS | Связывать с перевозкой и документами, а не присваивать владение урожаем |
| Показатель отчёта | Владелец методики; BI отвечает за реализацию формулы | Сохранять происхождение, полноту и время обновления |

## Допущения первого среза

| ID | Допущение | Последствие / что пересмотреть |
|:---|:---|:---|
| A-01 | В сезоне один участок содержит один сорт | Ключ `(plot_id, season)`; при смешанной посадке нужна сущность блока посадки |
| A-02 | Одна регистрация соответствует одной партии; полная приёмка однократна | Разделение, смешение и частичная приёмка требуют строк приёмки и связей происхождения N:M |
| A-03 | Сезон совпадает с календарным годом сбора | Проверка даты и отчёт; при другом сезоне нужен календарь сезонов |
| A-04 | Зарегистрированные факты неизменяемы | Исправление после регистрации блокирует выпуск бизнес-процесса до определения корректировочного документа |
| A-05 | Источники закрепляют устойчивые локальные ключи перед переключением | Координата строки Excel остаётся происхождением, но не идентификатором факта |
| A-06 | Утверждённые справочники передаются согласованным срезом | Транспорт обновления справочника и его API редактирования вне текущего контракта |

До промышленного запуска нужно согласовать корректировки, частичные приёмки, расхождения измерений, подтверждение плодоносящей площади и срок хранения исходных документов. Эти вопросы связаны с [Use Case](use-cases.md) и [переходом данных](migration.md).
