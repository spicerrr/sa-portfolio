# 🔄 от документа сбора к приёмке

## AS-IS

Производственный учёт переносит документ сбора в журнал с локальными кодами участка и сорта. Склад создаёт собственный документ, используя свой код номенклатуры. Аналитик получает два снимка и таблицу посадок. Сопоставление сорта и сопоставление фактов выполняются отдельно; одинаковый сорт не означает одинаковый сбор.

![UML Activity: AS-IS](../diagrams/rendered/as-is-process.svg)

[PlantUML](../diagrams/as-is-process.puml). Документы, их ключи и дефекты заданы в [исходной модели данных](as-is-data.md). Ручная связь подтверждается владельцами документов; неоднозначность сохраняется как результат сверки.

## TO-BE

![UML Activity: TO-BE](../diagrams/rendered/to-be-process.svg)

[PlantUML](../diagrams/to-be-process.puml) · [BPMN обмена Production / WMS](../diagrams/batch-process.bpmn).

| Контрольная точка | Ответственный | Условие продолжения | Исключение |
|:---|:---|:---|:---|
| Согласование сорта | НСИ + главный агроном | Один утверждённый ключ → один сорт | UC-01: `UNRESOLVED` |
| Проверка документа | Производственный учёт | Устойчивый исходный ключ, сорт, участок, дата, масса | UC-02: ошибка без сохранения |
| Регистрация | Production | Commit партии, идемпотентности и outbox | Повтор с тем же ключом |
| Создание ожидаемой приёмки | WMS consumer | Commit inbox и ожидаемой приёмки | Retry / DLQ |
| Подтверждение груза | Кладовщик | Полная приёмка с `batchId` и собственной массой | UC-03 / UC-05 |
| Обновление отчёта | BI consumer | Связанные факты, контроль полноты | Отложенная связь / признак устаревания |

`201 Created` подтверждает производственный факт. Publisher confirm подтверждает принятие сообщения брокером. Consumer ack подтверждает обработку одним потребителем. Ни одно из этих подтверждений само по себе не означает, что кладовщик принял груз.

## Изменение процесса

Повторный ввод реквизитов заменяется ожидаемой приёмкой из события. Связь по текстовому номеру заменяется `batchId`. Сверка остаётся для истории, исключений и расхождений измерений. Распределение ответственности — в [реестре ролей](stakeholders.md), полные пользовательские сценарии — в [Use Case](use-cases.md).
