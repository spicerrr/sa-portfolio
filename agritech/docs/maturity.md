# 🧩 диагностика цифровой зрелости

План обследования связывает состояние процессов с конкретными свидетельствами. Оценки компании здесь не заданы; для заключения нужны документы и подтверждения владельцев.

| Домен | Проверяемый вопрос | Необходимое свидетельство | Связь с требованиями |
|:---|:---|:---|:---|
| Процессы | Где повторный ввод и кто согласует исключения? | Карта процесса, интервью, журнал исключений | AS-IS / TO-BE |
| Данные | Есть ли единый ID и владелец справочника? | Справочник, mappings, правила изменения | BR-01 |
| Системы | Кто владеет каждым фактом? | Карта систем, ответственность | context.md |
| Интеграции | Как обнаруживают потерю или повтор? | Контракты, журнал доставки, сверка | FR-03 / FR-04 |
| Аналитика | Одинаково ли трактуется метрика? | Формула, гранулярность, источник | BR-04 / FR-05 |
| Управление изменениями | Можно ли восстановить согласованную версию? | История, review, релизный срез | versioning.md |
| Компетенции и ответственность | Кто утверждает правило и разбирает сбой? | Матрица ролей, регламент | MDM и DLQ |

Шкала обследования: 0 — подтверждено отсутствие практики; 1 — локальная ручная практика; 2 — согласованный повторяемый процесс; 3 — контроль через метрики и журнал; 4 — регулярное улучшение по измерениям. Если свидетельств недостаточно, оценка остаётся неизвестной; значение 0 не присваивается автоматически.

Для каждого наблюдения сохраняются источник, дата, владелец подтверждения, статус проверки и доступность публикации. Приоритет изменения зависит от бизнес-последствия: отсутствие mapping блокирует регистрацию; оформление отчёта не имеет такого же влияния. Числа экономического эффекта без исходных измерений не используются.
