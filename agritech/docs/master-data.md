# 🗂 справочники и соответствия кодов

Справочник сортов связывает локальные записи производства, склада и учёта с единым сортом. Название используется для отображения и поиска; основная связь строится по кодам.

## Один сорт в разных источниках

| Источник | Локальный код | Название | Единый код сорта |
|:---|:---|:---|:---|
| Учётная система ERP | `ERP-V-104` | Golden Delicious | `VAR-017` |
| Складская система WMS | `WMS-V-22` | Голден | `VAR-017` |
| Исходный производственный реестр LEGACY | `LEG-V-7` | ГОЛДЕН ДЕЛИШЕС | `VAR-017` |

Для потребителя единый сорт передаётся так:

```json
{"varietyId":"VAR-017","canonicalName":"Golden Delicious","status":"ACTIVE"}
```

`varietyId` — единый код, `canonicalName` — утверждённое название, `status` — состояние записи. Локальные коды и исходные имена сохраняются, чтобы можно было вернуться к первоисточнику.

## Кто подтверждает соответствие

Ответственный за справочники готовит решение, главный агроном подтверждает, что записи обозначают один сорт. Решение содержит локальный код, единый код, основание, автора, согласующего и дату. В [UC-01](use-cases.md) показана последовательность согласования.

[Файл соответствий](../examples/source-mappings.csv) содержит утверждённые связи для потребителей. История решений хранится в управляемом реестре и версиях выпуска. Таблица `source_mapping` в производственной БД содержит актуальную копию этих связей.

## Порядок сопоставления

1. Получить код и название сорта, название системы-источника и дату выгрузки.
2. Для поиска кандидатов убрать лишние пробелы и привести текст к единому регистру и форме Unicode NFKC.
3. Проверить, есть ли утверждённое соответствие для сочетания системы, типа сущности и локального кода.
4. Если соответствия нет, присвоить состояние `UNRESOLVED` — сорт не определён — и передать запись ответственному.
5. Ответственный сравнивает атрибуты и подтверждает решение с агрономом. Изменение уже утверждённой связи требует проверки исторических записей.
6. Передать потребителям согласованную версию справочника и зафиксировать её номер и время обновления.

Совпадение нормализованных названий предлагает кандидата, но не подтверждает связь. Переименование сорта сохраняет его код. Отключение сорта запрещает новые регистрации, сохраняя ссылки в истории.

## Проверки перед выпуском

| Что проверяется | Что делать при ошибке |
|:---|:---|
| Один локальный код связан с двумя сортами | Остановить выпуск и передать конфликт ответственному |
| Единый код отсутствует в справочнике | Остановить загрузку соответствия |
| Соответствие ещё не подтверждено | Оставить запись неразрешённой; сбор по ней не регистрировать |
| Названия различаются только написанием | Проверить кандидата и получить подтверждение |
| Сорт отключён | Разрешить просмотр истории, отклонить новый сбор |

Сорт, тип операции и единица измерения относятся к справочникам. Партия сбора и складская приёмка — отдельные производственные факты со своими документами и датами.

[Исходные записи](../examples/source-records.csv) и [скрипт проверки](../scripts/normalize.py) показывают два подтверждённых соответствия и один неизвестный код.
